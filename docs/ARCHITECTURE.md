# Архитектура FieldRoute AI

**Версия:** `v0.6.9 stable`

## Схема

```text
┌──────────────────────────────────────────────────────────┐
│ Browser UI                                               │
│ HTML / JavaScript / MapLibre GL JS                       │
│ KPI · карта · инженеры · проблемы · Demo Mode            │
└────────────────────────┬─────────────────────────────────┘
                         │ REST
                         ▼
┌──────────────────────────────────────────────────────────┐
│ FastAPI                                                  │
│ dataset · import · explain · problems · replan           │
└───────────────┬─────────────────────────────┬────────────┘
                │                             │
                ▼                             ▼
┌───────────────────────────────┐  ┌───────────────────────┐
│ Optimization                  │  │ Routing               │
│ Google OR-Tools               │  │ OSRM Table / Route    │
│ VRPTW / time windows / skills │  │ road time / geometry  │
│ vehicle compatibility         │  └───────────┬───────────┘
└───────────────┬───────────────┘              │
                │                              ▼
                │                    Haversine / straight
                │                    fallback on failures
                ▼
┌──────────────────────────────────────────────────────────┐
│ Result                                                   │
│ routes · assignments · KPI · explanations · replanning   │
└──────────────────────────────────────────────────────────┘
```

## Frontend

Интерфейс работает в браузере и включает:

- выбор региона;
- KPI;
- интерактивную карту;
- список заявок;
- список бригад;
- выделение отдельного маршрута;
- плановую позицию бригады;
- выбор стратегии оптимизации;
- Explainable Dispatching;
- вкладку проблем;
- Demo Mode;
- импорт CSV/XLSX.

## Backend

FastAPI предоставляет HTTP API для:

- встроенного датасета;
- baseline / optimized comparison;
- explainability;
- диагностики проблем;
- геометрии маршрутов;
- срочного перепланирования;
- пользовательского импорта;
- health check.

Основные служебные endpoints:

```text
/health
/docs
```

## Optimization layer

Google OR-Tools решает расширенную VRPTW-задачу с несколькими инженерами.

Обязательные ограничения:

- skill compatibility;
- vehicle compatibility;
- job time windows;
- engineer shifts.

В конкурсной стратегии порядок приоритетов кодируется доминирующими стоимостями:

```text
неназначенная обычная заявка = 100 000 000
неназначенная срочная заявка = 300 000 000
активация инженера           =   2 000 000
стоимость дуги               = дорожное расстояние в метрах
```

Это практически реализует порядок:

```text
максимум назначенных заявок
→ минимум задействованных инженеров
→ минимум суммарного пробега
```

Формально это единая функция стоимости с доминирующими штрафами, а не несколько последовательных независимых запусков оптимизатора.

Основной и аварийный solver используют лимит поиска 10 секунд.

## Routing layer

OSRM используется в двух ролях:

1. **Table API** — дорожное время и расстояния для матрицы оптимизации.
2. **Route API** — дорожная геометрия для отображения маршрутов.

При недоступности внешнего routing backend предусмотрены fallback-механизмы:

- для матрицы — `haversine-fallback`;
- для геометрии — прямые отрезки либо смешанная road/fallback-геометрия.

## Dynamic replanning

При срочном событии система:

1. фиксирует завершенные и выполняемые работы;
2. переносит стартовую позицию инженера к последней известной плановой точке;
3. формирует оставшийся горизонт;
4. добавляет срочную заявку;
5. повторно запускает OR-Tools на остатке дня;
6. рассчитывает изменения назначений, маршрутов и Plan Stability.

## Deployment

Прототип может запускаться локально или как FastAPI web service.

Текущий публичный стенд:

```text
https://fieldroute-ai-lct2026-final.onrender.com/
```

Deployment выполняется на Render. Текущий конкурсный стенд может иметь cold start после периода бездействия на Free compute.

## Внешние зависимости

- публичный OSRM используется как внешний routing backend;
- MapLibre GL JS / OpenStreetMap используются для визуализации;
- persistent production database в конкурсном MVP не используется.
