## Что отсутствует в исходных заявках

В предоставленных материалах нет полного набора данных для промышленного расписания, в частности не все необходимые сущности представлены отдельными полями.

Для MVP используются явно документированные правила.

### Roster инженеров

Имена бригад извлекаются из контрольного распределения.

Для демонстрационного roster детерминированно задаются:

- квалификации;
- тип транспорта;
- рабочая смена.

### Требование транспорта

Так как отдельное поле требуемого транспорта отсутствует у исходных заявок, для части заявок требование добавляется детерминированным demo-правилом. Это позволяет проверить обязательный resource constraint.

### Приоритет

Заявки типа `Авария` интерпретируются как срочные. Остальные — как обычные.

### География

Исходные CSV содержат адреса, но не координаты.

Встроенный датасет использует:

```text
district-centroid-fallback
```

Это:

1. центр известного района/города;
2. небольшое детерминированное смещение, вычисленное из адреса.

Поэтому OSRM строит реальные дороги между используемыми точками, однако сами точки не являются результатом точного промышленного геокодирования.

## Пользовательский импорт

Интерфейс поддерживает CSV/XLSX для инженеров и заявок.

Для предсказуемой проверки рекомендуется использовать файлы-шаблоны из верхней панели приложения.

## Интерпретация результатов

Все KPI прототипа следует трактовать как результаты конкурсного моделирования на предоставленных и синтетически дополненных данных, а не как измеренные показатели производственной эксплуатации.
